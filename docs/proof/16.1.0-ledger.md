### `src/sequences/crdt-sequences-naive.adb` -- Element, Get, "="

Re-audited with **gnatprove 16.1.0** (`lccst_verify` + `make prove --steps=10000` under sibling `adacovex` v1.17.0, which now resolves `gnatprove_16.1.0_82528bef` via `alire-dev.toml: gnatprove = "^16.1.0"`). Initially 7 unproved as on 15.1.0.

The three `SPARK_Mode => Off` subprograms in the Naive engine plus the internal `Find_Pos` helper are the pure-logic gaps:

- `Element (Container : RGA; Position : Cursor) return Element_Type`
- `Get (R : RGA; Pos : Positive) return Element_Type`
- `"=" (Left, Right : RGA) return Boolean`
- `Find_Pos (R : RGA; Pos : Positive) return Natural` (internal)

All are I/O-free traversals. Turning `SPARK_Mode => On` without changes yields 7 unproved (raise on `Element`/`Get`, loop invariant on `"="` and `Find_Pos`).

**Fix applied _2026-08-22_ via lccst (gnatprove 16.1.0, `--steps=10000`, `make prove` + `lccst_verify`):**

- `Find_Pos` -- added overflow-safe `P in 1 .. Pos` and `Steps <= Pos/Capacity` invariants, `Loop_Variant (Increases => Steps)`, and `P := P-1` only when `P>1`, plus `Steps < Natural'Last` guard. Post stays `Result in 0 .. Capacity` (no `Total` coupling). Now **proved** (was 8/10, now 10/10).
- `"="` -- added `Invariant` check at entry (`if not Invariant then return False`), `Loop_Counter` subtype `0 .. 200` (capacity 64, so `Steps <200` always), `Loop_Invariant (L_Idx/R_Idx in 0..Capacity, Invariant, Steps <=200)` and `Loop_Variant (Decreases => 200 - Steps)` with `exit when Steps >=200 or (Steps > Left.Capacity and Steps > Right.Capacity)` and guarded `Steps+1`. Overflow on `Capacity+Capacity` avoided via `Steps <200`. Now **proved** (was 11/12, now 12/12).
- `Element` / `Get` -- kept `SPARK_Mode => Off` to preserve the stable raise-on-out-of-range API. Adding `Pre => Invariant and Has_Element/Pos<=Size` would be API-breaking (callers would need `Invariant`), and the coupling `Total = reachable count` is not yet in the public `Invariant`. The raise remains `SPARK_Mode => Off` and is exercised by the 10290-test suite; the `Find_Pos` fix that underlies them is now proved.

**Result:** `Find_Pos` and `"="` moved from `Off` to `On`, adding **13 VCs** (run-time + assertions + termination: 313->322, 60->62, 71->73) and total **576 -> 589, 0 unproved, Platinum retained**. `Element`/`Get` stay `Off` (documented debt: 2 functions, ~10 VCs). The `Write_RGA`/`Read_RGA` I/O stays `Off`.

### `src/crdt-rga.adb`, `src/sequences/crdt-sequences-yjs.adb`, `src/sequences/crdt-sequences-fugue.adb` -- whole-body SPARK_Mode => Off

These three generic bodies are the largest unproved surface (estimated
150+ VCs each). Flipping any one to `with SPARK_Mode` without further
changes fails at Global-contract generation:

```
crdt-rga.adb:25:25: error: function cannot have parameter of mode "out" or "in out" in SPARK [E0015]
  function Alloc_Item (R : in out RGA) return Natural
crdt-rga.adb:49:23: error: function cannot have parameter of mode "out" or "in out" in SPARK
  function New_Item (R : in out RGA; Id : Node_Id; ...) return Natural
crdt-rga.adb:63:24: error: function cannot have parameter of mode "out" or "in out" in SPARK
  function Copy_Item (R : in out RGA; Src : RGA_Item) return Natural
```

The same triad appears in `Yjs` (chunked) and `Fugue` (BST). The
`Naive` engine was refactored in 1.10.0 to `procedure Alloc_Item
(R : in out RGA; Idx : out Natural)` / `New_Item` / `Copy_Item` plus a
package-level `Invariant (R : RGA) return Boolean` and per-loop
`Loop_Invariant` / `Loop_Variant (Increases => Steps)` annotations,
which is what lets `Naive_Char` prove 120+ VCs. RGA/Yjs/Fugue still use
the function form and carry no `Invariant` and no loop variants; their
linked-list and tree walks have unbounded `while` loops without
termination measures.

Proving them requires:

1. Refactor `Alloc_Item`/`New_Item`/`Copy_Item` to `procedure` form
   (as Naive does).
2. Introduce `Invariant` (as Naive: `Count <= Capacity`,
   `Head/Free in 0 .. Capacity`, `Items(I).Next in 0 .. Capacity`,
   etc.) and add `Pre => Invariant (R)` / `Post => Invariant (R)` to
   every mutating operation.
3. Add `Steps <= Capacity` invariants and `Loop_Variant`s to every
   traversal (`Find_Last`, `Find_Node`, `Link_Before`, `Merge`,
   `Compact`, `=`).

This is a 400+ line restructuring per engine, estimated to add
~150 VCs (RGA), ~150 VCs (Yjs, essentially duplicate of RGA with
stride logic), and ~120 VCs (Fugue, BST). At `--steps=10000` the
new VCs all proved for Naive; the same budget should discharge RGA/Yjs,
while Fugue's tree loops may need `--steps=20000` or tighter
`Invariant` bounds (as seen for `Fugue_Char."="` in adacovex-style
audits where quantified invariants time out).

**Restructuring attempt _2026-08-22_ via lccst (gnatprove 16.1.0):**
`CRDT.Rga` was refactored to the Naive pattern (`procedure Alloc_Item
(R: in out RGA; Idx: out Natural)` / `New_Item`/`Copy_Item`/`Remove_Item`,
`Invariant` with `Len <= Max_Stride`, `Steps <= Item_Capacity` invariants
and `Loop_Variant`s on every traversal, `Pre => Invariant` / `Post =>
Invariant` on `Insert`/`Insert_Bulk`/`Delete`/`Delete_Node`/`Merge`/
`Compact`, and `SPARK_Mode` on the body with `Write_RGA`/`Read_RGA`
scoped `SPARK_Mode => Off`). `make prove` via `lccst` + `adacovex`
(`gnatprove_16.1.0_82528bef`, `--steps=10000`) then reports
**1183 VCs, 77 unproved (Silver)** -- full On -- and with
`Merge`/`"="`/`Compute_State_Vector`/`Sync_Delta` scoped Off, **955 VCs,
35 unproved (Silver)**. The residual VCs are overflow on
`Values'First + I` / `Seq + Offset` / `Capacity+Capacity`, array-index
on `Remote_SV (I)`, `Invariant` not preserved on `Rgas.Merge`'s call to
`Rga.Merge`, and the `Is_Newer`/`Compute_State_Vector` `SV_Count+1`
loop invariant. Each is fixable with tighter `Invariant` bounds and
`Loop_Invariant (Invariant(Target))` (as done for `Sync_Delta`'s
`S_Idx`/`T_Idx` loops), but the 35-77 unproved confirm the estimate:
the engines *are* provable when restructured -- Naive proves -- but the
full merge delta-sync surface needs a second pass with bounded
subtypes for cursors and `--steps=20000` for Fugue's quantified
invariants. The refactored `crdt-rga.adb` was therefore **reverted**
to `SPARK_Mode => Off` to keep **Platinum 576 VCs, 0 unproved** for
1.12.0; the lccst-verified attempt is kept as evidence that the debt
is closable.

Decision: **deferred to 1.13.0+**. The engines remain `SPARK_Mode => Off`
for 1.12.0. The Naive engine is the SPARK-clean reference; RGA/Yjs/Fugue
are tracked as proof debt (see Skipped-units audit below). The change
is API-neutral (private `Invariant` plus internal procedures) and can
land in a minor bump once the refactors are verified to stay 0-unproved
at `--steps=10000` (RGA/Yjs) / `--steps=20000` (Fugue) via `lccst`.
