# Quality gates and make targets

This page lists every `make` target in the CRDT repository, what it checks, and
when you must run it. It is the on-site version of the target list in the
`Makefile` and of the gate order in [AGENTS.md](https://github.com/bladeacer/Ada_CRDT/blob/main/AGENTS.md).
Run `make help` for the same list in your terminal.

## Before you commit

`make check` is the pre-commit gate. It runs the cheap static gates first, then
the build, the test suite, the proof, and the generated reports, in this order:

| Order | Gate | What it proves |
|-------|------|----------------|
| 1 | `ascii-check` | Every source file holds only ASCII characters |
| 2 | `changelog-check` | Every changelog follows the canonical `C#`/`H#` format |
| 3 | `link-check` | Every Markdown link and heading anchor resolves |
| 4 | `docs-check` | The prose rules hold: paragraph cap, sentence spacing, no em dash, no Latin abbreviation |
| 5 | `fmt` | `gnatformat` has formatted every Ada source |
| 6 | `doc` | The API reference and the changelog index are regenerated |
| 7 | `spark-off-check` | Every `SPARK_Mode => Off` location appears in the coverage report |
| 8 | `build` | The library and the test suite compile |
| 9 | `test` | All 10332 tests pass, including the fuzz and Game of Life categories |
| 10 | `prove` | gnatprove reports 0 unproved and 0 justified checks |
| 11 | `coverage-gate` | Docstring coverage did not fall below the last release tag |
| 12 | `compliance` | Every HLR tag has a requirement, and the verification report is current |
| 13 | `description` | The crate description matches `alire/description.txt` |

After the reports, the gate runs three count-sync checks. `test-count` and
`proof-status` verify that no file still carries a stale test or proof number,
and `doc-links` verifies that the Documentation block of `AGENTS.md` matches
`tools/doc-links.map`.

A gate that rewrites a file is not a gate you can ignore. Run `make check`, then
commit the files it changed.

## The prose gate

`make docs-check` runs `tools/check-docs.py`, which enforces four rules on the
hand-written Markdown, the changelogs, the root `README.md`, and the comment
text of every Ada source under `src/`:

| Rule | Limit | Fix |
|------|-------|-----|
| Paragraph length | Four sentences per paragraph | `python3 tools/para-split.py --fix` |
| Sentence spacing | One space after `.`, `!`, or `?` | `python3 tools/check-docs.py --fix` |
| Em dash | None, in prose or comment | Write the clause as two sentences |
| Latin abbreviation | None, so `e.g.`, `i.e.`, and `etc.` are out | Write the full form |
| File length | 250 lines, a soft cap | Split the page, or mark it |

The line cap is a warning, not a failure. A reference page opts out with a
`no-crdt-docs-loc` marker in an HTML comment near its top. The marker is for
content whose length is the content: the requirement register, the
requirement mapping, the proof ledger, the Technical Names dictionary, the
README, and the changelog history.

The gate reads an Ada line only from its `--` marker on, so code alignment and
string literals are outside the rules. Both fixers are safe to run: the
paragraph fixer inserts blank lines only, and the spacing fixer collapses a
double space only where the gate would fail.

## Single-purpose targets

| Target | What it does | When you need it |
|--------|--------------|------------------|
| `build` | Compiles the library and the test binary | First build, or after a toolchain change |
| `test` | Runs the whole suite, fuzz category included | After any behaviour change |
| `prove` | Runs gnatprove and refreshes the SVG badges | After any change to a SPARK unit |
| `demo` | Runs the three-replica Game of Life terminal demo | To see convergence on a live workload |
| `doc` | Runs gnatdoc, then `rst2md.py`, then the index generators | After any docstring change |
| `sbom` | Writes the proof-aware CycloneDX `sbom.json` | Before a release |
| `compliance` | Regenerates `VERIFICATION.md` and checks HLR traceability | After a proof or test change |
| `fmt` | Formats all Ada sources | Before a commit |
| `clean` | Removes `obj/`, `lib/`, and `docs/` build products | When a build looks stale |

## The generated files

Four files in the repository are generated, and a change to them without a
change to their source is a defect. The gates catch most of these, but review
the diff before you commit:

| Generated file | Source of truth | Regenerated by |
|----------------|-----------------|----------------|
| `docs/api-docs/*.md` | Docstring comments in `src/**/*.ads` | `make doc` |
| `docs/api-docs/crdt-spark-coverage.md` | Every `SPARK_Mode => Off` location | `make doc` |
| `docs/changelogs/index.md` | The `docs/changelogs/crdt-*.md` files | `make doc` |
| `docs/compliance/VERIFICATION.md` | `obj/gnatprove/gnatprove.out` and `test_result.md` | `make compliance` |
| `sbom.json` | The manifests, the source tree, and the proof output | `make sbom` |

## The two manifests

`alire.toml` is the publishing manifest. It carries no development dependency
and no executable entry, because it is what the Alire index receives. The
development dependencies, `gnatprove`, `gnatdoc_bin`, `gnatformat_bin`, and
`covex`, live in `alire-dev.toml`.

The `fmt`, `doc`, `prove`, `coverage-gate`, and `sbom` targets swap
`alire-dev.toml` over `alire.toml` for the length of the command and restore the
publishing manifest afterwards. You never switch the manifest by hand.

## Continuous integration

The three GitHub Actions workflows run the same targets. `ci.yml` runs the build,
the tests, the proof, the compliance check, and the release checks.
`pr-check.yml` runs the pull-request subset, and `release.yml` runs on a `v*` tag
and adds the SBOM, the Sigstore attestation, and the GitHub release. The full
job list and its local equivalents are on the [CI/CD page](../ci-cd.md).
